# 炼知 ReKnow · 炼金宇宙 —— 网站构建指导

> 本文档是开发团队的「施工图」：架构原则、文件分工、实施顺序、协作流程。
> 配套阅读：《项目策划书.md》（做什么、为什么做）。本文档讲「怎么做」。

---

## 一、架构总图

```
┌─────────────────────┐          ┌──────────────────────────┐
│  前端（浏览器）       │  网络请求  │  后端（server.js + SQLite）│
│  index.html/app.js  │ ◄──────► │  · 账户认证（JWT）         │
│  universe.js(3D)    │          │  · 数据库（users/progress） │
│  tldraw 白板         │          │  · 保管 AI Key、知乎 token  │
└─────────────────────┘          └───────┬──────────┬───────┘
                                          │          │
                                   大模型 API    知乎官方 API
                                  （已有 Key）  （赛事方提供）
```

**第一原则：浏览器里只放「面子」，服务器上才放「里子」。**
所有钥匙（AI Key、知乎 access token）、所有数据（账户、进度、批注、白板）只在后端和数据库出现；前端任何代码都可被用户查看，绝不放密钥。

## 二、文件分工（现有）

| 文件 | 职责 | 改动原则 |
|---|---|---|
| `index.html` | 主应用骨架 + 全部 CSS | 改版时主要动它 |
| `app.js` | 学习闭环全部逻辑（13 万字符单体） | 含两代代码，靠函数声明覆盖；**不大改结构，只在外层扩展** |

| `vendor/three.min.js` | Three.js r160 UMD（离线） | 不动 |
| `assets/*.gif` | 看山官方 6 动作 | 不动 |

## 三、实施顺序（六步，每步独立交付、互不推翻）

> 排序原则：先骨架后皮肉；同文件攒批改；每步完成即 `git commit`。

### 第 0 步：需求冻结清单
列出全部界面/交互修改点，先规划不动手，消解冲突与重复。

### 第 1 步：账户系统 + 云端同步（骨架）
- 后端：加 SQLite（`data/reknow.db`），建表 `users` / `progress` / `annotations` / `whiteboards`；
- 接口：`POST /api/register`、`POST /api/login`（bcrypt 哈希密码 + 签发 JWT）、`GET/POST /api/mydata`；
- 前端：登录/注册弹窗；localStorage 保留为离线缓存，登录后自动与云端同步（登录时云端覆盖本地，操作后后台静默上传）；
- 验收：开两个浏览器各注册一个账号，互不可见对方数据；换浏览器登录能取回进度。

### 第 2 步：AI 助手小窗
- 后端：`POST /api/ai/chat`，带着 API Key 请求大模型（流式转发 SSE）；
- 前端：右下角气泡 → 展开侧小窗，流式打字显示；在学习/宇宙任何页面都可唤起；
- 顺手升级：现有「AI 开杠」从模板话术切换为真实模型（保留三档强度提示词）；
- 安全：Key 只存在于后端环境变量 / 本地 `.env`（已在 .gitignore）；
- **模型抽象层**：AI 调用统一封装为「OpenAI 兼容格式」（base URL + Key + 模型名三个参数），为第 2.5 步的"用户自配模型"留好接口——默认用官方 Key，允许用户填入自己的开源模型端点。

### 第 2.5 步：个性化系统「炼金配方」
> 这是"伴随成长"的落地方案，必须在知乎接入与改版**之前**完成，因为后续功能都要读取配方。

**数据结构**：每用户一份配方 JSON，云端存 `users` 表的 `recipe` 字段，本地缓存于 localStorage 键 `rkRecipe`：

```json
{
  "intake":  { "manualPick": true, "aiFilter": true },        // 进库两步，各自开关
  "depth":   { "level": "standard" },                          // shallow | standard | deep
  "pipeline": ["拆解", "学懂", "图谱", "融汇", "回流"],          // 可增删、可重排
  "ai":      { "provider": "default", "baseUrl": "", "model": "", "key": "" },  // 自配模型（OpenAI 兼容）
  "review":  { "enabled": false, "perTopic": {} }              // 复习总开关 + 按主题设置
}
```

**前端三载体**：
1. 设置页（全局配方管理）；
2. 各功能旁小齿轮 ⚙️（局部调整即时写回配方）；
3. 配方导入/导出 JSON 文件（可分享）。

**划分原则：高频、作用范围只在"当前这一篇/当前场景"的进小齿轮；低频、影响全局或涉及密钥安全的进设置页。**

| ⚙️ 小齿轮（边用边调 · 高频 · 局部） | 🛠 设置页（低频 · 全局 · 敏感） |
|---|---|
| 本篇拆解档位临时换档 | 默认拆解档位 |
| 本篇 AI 开杠强度 | 进库规则（手动挑 / AI 粗筛开关） |
| 本篇是否加入复习 | 流程编排（关闭 / 重排 / 还原） |
| 天气 / 昼夜模式 / 音效静音 | AI 模型接入（provider / baseUrl / Key） |
| 当前知识点一键贴入白板 | 复习总开关与按主题计划 |
| 字号 / 阅读密度 | 账户管理、数据与配方导入导出 |

**行为约定**：
- 进库：`manualPick` 与 `aiFilter` 决定收藏夹列表的呈现与预筛逻辑；
- 拆解：`depth.level` 决定拆解提示词与知识点数量（浅尝 3 个 / 标准结构化 / 深挖强制第一性原理追问）；
- 流程：`pipeline` 数组驱动顶栏与步骤条的渲染——被关闭的环节从主流程中收起、默认不渲染，但**入口保留在"流程管理"面板中，可随时一键还原**（软关闭，不是删除）；
- AI：`ai.provider === "custom"` 时后端把请求转发到用户自配端点，用户 Key 仅存于该用户的服务端记录，绝不入前端代码与 git 仓库；
- 成长：升级所需经验改为**逐级递增曲线**（调整 `app.js` 的 `LEVELS`，例如 need 按 ~1.5 倍几何增长）。

### 第 3 步：知乎官方 API 接入
- 向赛事方获取 API 文档与应用凭证；
- 后端实现 OAuth 五步走：跳转知乎授权页 → 回调取 code → 换 access token → 存 token（关联到用户账户）→ 调收藏夹接口；
- 前端：「绑定知乎」按钮 + 收藏夹列表；选中即进入现有「拆解 → 学懂」流程，并在宇宙中生成新星球；
- 兜底：无 API 环境下仍用 `data.js` 演示数据自洽运行（评委离线可演示这一点不能丢）。

### 第 4 步：无边记白板（tldraw）
- `npm` 引入 tldraw（或 vendored 构建），顶栏加「📋 白板」入口，全屏覆盖层承载；
- 白板文档 JSON 存入第 1 步的 `whiteboards` 表 → 多设备同步；
- 学习中可随时把当前知识点一键"贴"到白板。

### 第 5 步：页面与交互整体改版
- 功能齐备后，一次性重排布局 / 交互 / 视觉，避免返工；
- 改版只动 `index.html` 的 CSS 与容器结构，学习闭环逻辑保持不变。

## 四、团队协作流程（git）

> 真身在 GitHub：https://github.com/zzz11225566/reknow-universe
> 每个协作者的纪律：**开工先 `git pull`，完工即 `git push`。**

```bash
git pull                          # ① 对齐真身（绝不能跳过）
# …… 改代码 ……
git add -A
git commit -m "写清改了什么"
git push                          # ② 更新真身
```

- 首次参与：`git clone https://github.com/zzz11225566/reknow-universe.git`；
- push 被拒绝 = 有人在你之后推了新版，先 `git pull` 合并再 push；
- 禁止：`git push --force`、删历史、改 `.git` 目录；
- 冲突处理：停下来找对方确认，不擅自取舍。

## 五、与 AI 协作者（AI agent）合作的高效约定

1. **一次会话只做一步**，开头注明「现在是第 X 步」，agent 只读相关文件；
2. 界面类修改附参考（截图 / 草图 / 参考站点），减少返工；
3. 每步结束由 agent 执行 commit + push，保持仓库随时干净；
4. 大文件（`app.js`）攒批修改，不零散多次重写。
